# Расписание Гимназии №19

Веб-интерфейс для просмотра расписания, подготовленного в программе «Ректор». Сайт показывает расписание по классам, учителям и кабинетам. Новая версия публикуется вручную тремя комплектами готовых HTML-файлов.

Рабочая версия: [rasp.gymn19.ru](https://rasp.gymn19.ru)

Пошаговая инструкция для сотрудника, который публикует расписание и назначает замены: **[Инструкция администратора](docs/ADMIN_GUIDE.md)**.

## Состав проекта

- `site/` — статический веб-интерфейс без серверного фреймворка;
- `server/upload-api/upload_api.py` — проверка и защищённая публикация HTML-экспортов;
- `server/install.sh` — первичная установка на Debian-сервере;
- `docker-compose.yml` и `nginx.conf` — запуск сайта в Docker;
- `server/rasp.gymn19.ru.conf` — обратный прокси и HTTPS для Nginx Proxy Manager;
- `server/rasp-cert-renew.*` — автоматическое продление сертификата Let's Encrypt.

Файлы актуального расписания в Git не сохраняются: экспорт может содержать имена сотрудников и локальные пути Windows. Они публикуются напрямую с рабочего компьютера на сервер.

## Запуск сайта

1. Скопируйте `.env.example` в `.env` и укажите адрес, на котором контейнер должен принимать соединения.
2. Поместите HTML-экспорт «Ректора» в `site/data/`.
3. Запустите:

```bash
docker compose up -d
```

По умолчанию сайт доступен на порту `8085`. Проверка состояния контейнера обращается к `/healthz`.

## Обновление расписания

В программе «Ректор» нужно отдельно сформировать три HTML-экспорта:

1. **Классы** — расписание по классам и группам.
2. **Учителя** — расписание по преподавателям.
3. **Кабинеты** — расписание по кабинетам.

Для каждого экспорта создайте отдельную папку. «Ректор» помещает в неё главный файл `index.html` и, при необходимости, нумерованные страницы `index0.html`, `index1.html`, `index2.html` и далее. Количество страниц зависит от расписания.

На сайте нажмите **«Загрузить расписание»** и в каждом из трёх полей выберите сразу все файлы `index*.html` из соответствующей папки. Обязательно выбираются:

- `index.html`;
- все созданные рядом файлы `index0.html`, `index1.html`, `index2.html` и далее.

Файлы нельзя переименовывать или смешивать между разделами. После ввода пароля сервер проверит комплектность всех трёх наборов, сохранит резервную копию текущего расписания и опубликует новую версию. Фоновая проверка программы «Ректор» на рабочем компьютере не используется.

## Админ-панель, замены и свободные кабинеты

Кнопка **«Админ-панель»** открывает защищённый раздел. После ввода пароля создаётся восьмичасовая серверная сессия; повторно вводить пароль для загрузки расписания или сохранения замен не требуется.

В разделе **«Замены»** выберите отсутствующего учителя и точный диапазон дат. Система создаёт календарный список его уроков, автоматически подставляет время по расписанию звонков и предлагает свободных преподавателей. Приоритет: учитель того же предмета, затем учитель, работающий с классом. Если оба варианта недоступны, автоматическая замена не назначается, но администратор может выбрать другого свободного учителя вручную.

Проверка конфликтов учитывает дату, номер и время урока, собственное расписание преподавателя, ранее сохранённые замены и периоды отсутствия. План сохраняется только после выбора замены для каждого урока. Период ограничен 63 днями.

Кнопка **«Свободные кабинеты»** показывает все кабинеты без занятий в выбранный день и номер урока. При публикации нового полного комплекта HTML временные замены очищаются.

## Безопасность

- контейнер можно привязать только к внутреннему адресу;
- внешний доступ проходит через Nginx Proxy Manager;
- HTTP перенаправляется на HTTPS;
- сертификат Let's Encrypt проверяется и продлевается системным таймером;
- SSH-ключ издателя имеет отдельную учётную запись и используется только для загрузки новых выпусков.
- пароль загрузки хранится вне Git в `.env`;
- принимаются только полные комплекты файлов `index*.html` общим размером до 16 МБ;
- перед каждой публикацией сервер архивирует предыдущую версию расписания.

## Версии

Текущая версия хранится в файле `VERSION`. Каждое изменение проекта оформляется отдельным Git-коммитом, а готовые версии отмечаются тегами `vX.Y.Z` и описываются в `CHANGELOG.md`. На сайте версия отображается как `Версия rasp.gymn 2.2.3`. Исправления и небольшие изменения интерфейса повышают только последнюю цифру версии.
